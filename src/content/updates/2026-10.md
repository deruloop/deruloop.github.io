## Packd

### Trip Journal

Packd now has a writing surface that turns a trip into an editable article. It runs the [Konuq](https://konuq.app) editor inside Packd with a native theme, and it opens from the nav bar or from a prompt in the workspace.

Days and stops appear in the journal as live cards. Tapping one edits the stop, and new stops can be added from inside the journal. Locations are inline links that open in the default maps app, and existing journals were migrated.

### Also new

- **Publishing to Konuq.** A journal publishes straight to Konuq, and Packd remembers the note for each trip, so publishing again updates it in place. Cards become native Konuq blocks and photo captions carry across. If Konuq isn't installed, the button goes to the App Store.
- **Tags.** Published notes are tagged `#trips` by default, and the tag is configurable. Imported notes also carry `#packd`.
- **Text to trip.** Text shared from any app opens Packd, which offers a destination search and builds the trip with AI, or adds to an existing one.
- **Better reading of itineraries.** Day headings work in any language and are never mistaken for stops. Stops keep their order, durations come from written time ranges, untimed stops fit between fixed ones, and dates are inferred from headings. Packd only asks to finalize when it's genuinely unsure.
- **AI providers.** Providers can now be switched on and off in the app. The Pro gate only applies to the cloud key, so on-device AI stays open. Packd also moved to the VoltaSDK 1.1 line for Private Cloud Compute.
- **Smaller fixes.** Tapping a search result in the stop sheet now names the stop and shows the right address. The AI button says when it will replace existing content. The share sheet's trip list fills the space, with Save pinned to the bottom.

## VoltaSDK

### Evaluation engine

`VoltaSDKEvals` is a new library that goes in the test target and measures how well a model tier actually handles a feature. A task is a JSON file with the exact system instructions, about 20 realistic inputs, what a correct answer must contain, and the graders.

Each task runs against one tier (on-device, Private Cloud Compute or a cloud vendor) in three modes (raw prompt, structured output, structured plus one repair turn) under Apple's Evaluations framework from WWDC 2026. The output is a `capability-map.json` and `.md` with pass rates, per-grader rates, failure reasons and latency for each tier and mode.

### Model picker

`ModelSelector` gained a multiple mode for switching providers on and off. It feeds `AIConfiguration.enabledProviders`, which resolution, `canServe` and `preferred()` all respect. Single-pick mode stays.

### Also new

- **Graders and judges.** Deterministic graders come from a fixed registry. A model judge covers subjective quality, refuses to score its own vendor's tier, and isn't trusted until it agrees with human ratings (Cohen's kappa).
- **Handoff and long context.** Handoff evaluations reproduce a provider switch in the middle of a conversation, to measure quality when the chain silently falls back. Long-context tasks hide one recipe among many at growing page sizes.
- **Testing on real devices.** Hosted test bundles in both demo apps measure Private Cloud Compute from an entitled process and on-device from a real iPhone, and a script merges the results.
- **First real measurement.** On a client's Italian meal assistant, running on the Mac's on-device model, structured output took schema validity from 0% to 100% and two-turn item retention from unmeasurable to 100%. The assumption that a small on-device model can't hold a list across turns turned out to be false once output was structured. Content quality is what remained.
- **Structured output.** A vendor-neutral `OutputSchema` goes in and a validated value comes out, with one automatic repair turn and a typed error the chain can recover from. Each provider uses its native mechanism, and custom providers fall back to a prompted schema.
- **Capability gating at runtime.** An app bundles `capability-map.json`, sets `AIConfiguration.capabilities` and tags calls with `task:`. Providers below the floor are skipped and logged, unmeasured ones are still tried, and `canServe` says whether a feature can exist on the device's chain.
- **iOS build fix.** Versions 1.0.0 through 1.1.1 did not compile for iOS, because the Private Cloud Compute entitlement check used the macOS-only `SecTask`. Version 1.2.0 is the first 1.x release that builds for iPhone or simulator. On iOS the entitlement is now read from the code signature, with the provisioning profile as fallback, which also stopped App Store builds from silently resolving Private Cloud Compute to "absent".
- **Rate limiting.** On-device rate limiting now counts as unavailability, so the chain falls back instead of failing hard.

## Raviolo

- **Natural pantry input.** The pantry field reads several items on one line ("6 eggs, 500 g pasta, milk") and understands taking things out ("finished milk", "ho finito il latte", "used 200 g flour").
- **Cooked it.** A new button under a recipe card in chat and on saved recipes removes the stated amounts and says what's left. Pinches, spoons and handfuls leave the pantry untouched. This runs on rules, with no model.
- **Exact amounts.** Tapping the number on a pantry line allows typing the exact amount. Plus and minus step in sensible sizes (one egg, 100 g of flour, half a litre).
- **Shopping list from recipes.** Ingredients go on the list as what actually gets bought, so "3 tuorli" becomes 3 eggs and "la scorza di 2 limoni" becomes 2 lemons. Fractions, ranges and long unit names read properly, and kitchen measures are dropped ("a pinch of salt" is just salt).
- **Visible progress.** Adds waiting on the model now show it, with a banner on the list, a spinner on the recipe button and a small spinner on the Shopping tab. A tick or another add during the wait is kept. The list also makes fewer model calls and runs them in parallel.
- **Store sections.** Section names follow the app language, including stores built from a description and renamed sections.
- **Siri.** The action has been around since August, and it now takes one sentence. "Add to Raviolo shopping list" makes Siri ask what to add. The phrases are translated into Italian, French, Spanish and German, Settings has a new Siri section, and a one-time tip appears after the first add by hand. Adding an already ticked item un-ticks it instead of duplicating it.
- **Assistants.** Numbers, calories, diet and restrictions are no longer off limits in chat, while medical advice still stays out. Questions about where a food keeps (fridge, freezer, room temperature) now go to Amaretto.
- **Raviolo Plus.** It moved from GPT-4o mini to GPT-6 Luna.
